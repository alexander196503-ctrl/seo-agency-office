# AGENTS.md — инструкция для ИИ-агента

Ты работаешь с визуальным офисом AI-SEO-агентства владельца. Прочти это перед изменениями.

## Контекст

- `index.html` — единственный файл приложения: карта офиса (15 Senior-агентов, 6 отделов),
  приёмная директора с постановкой задач, демо-сценарии, досье и вопросы агентам.
  Никаких сборщиков и внешних зависимостей: чистые HTML+CSS+JS, всё инлайном.
- Данные агентов — объект `STAFF` в `<script>`; отделы — массив `ROOMS`;
  демо-сценарии — объект `SCEN`; модули автоматики — секция `.mods` в HTML.
- Дизайн: CSS-переменные в `:root` (светлая/тёмная тема через `prefers-color-scheme`
  и `data-theme`). Не ломай токены и обе темы.

## Правила агентства (кратко)

1. Каждый агент — Senior; Google, Яндекс и GEO/AEO — раздельные специализации.
2. Задачи проходят гейты G0–G6; исполнитель не принимает свою работу (QA независим).
3. Новые знания в базу — только через Trend Monitor (грейд A–D) и фактчек SME.
4. Спорные методы (ПФ, parasite и т.п.) — карточка гипотезы и явное согласование владельца;
   без него никаких внешних воздействий и трат.
5. Модели закреплены по функциям; замена — только через eval/canary/rollback.

## Как вносить изменения

1. Меняй `index.html`, сохраняя структуру `STAFF`/`ROOMS`/`SCEN`.
2. Проверь в браузере: офис в один экран, симуляция работает, обе темы читаемы.
3. Commit с осмысленным сообщением + push в `main` — Pages опубликует сам.
4. Если меняешь состав агентства (роли, отделы) — отрази это и в README.md,
   и сообщи владельцу: первоисточник архитектуры живёт в его Obsidian-vault
   (`projects/СЕО агенство/CLAUDE.md` и `00-HANDOFF.md`).

## Чего не делать

- Не добавлять внешние CDN/шрифты/трекеры — страница должна оставаться самодостаточной.
- Не публиковать секреты: репозиторий публичный.
- Не переименовывать `index.html` и не менять ветку публикации без запроса владельца.
